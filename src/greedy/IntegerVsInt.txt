In **Java**, `List<Integer>` is often **much slower than `int[]`** in algorithm problems because of **three main reasons**.

---

# 1️⃣ Autoboxing / Unboxing Overhead

Java collections cannot store primitives directly.
So when you use `List<Integer>`, every `int` must be converted to an **Integer** object.

Example:

```java
List<Integer> list = new ArrayList<>();
list.add(10);
```

What actually happens internally:

```java
list.add(Integer.valueOf(10)); // boxing
```

When retrieving:

```java
int value = list.get(0); // unboxing
```

Internally:

```java
int value = list.get(0).intValue();
```

So every operation adds **extra object creation and method calls**.

---

# 2️⃣ Memory Overhead

Primitive array:

```java
int[] arr = new int[1000000];
```

Memory per element:

```
4 bytes
```

But `List<Integer>`:

```
ArrayList → stores references (8 bytes each)
Integer object → ~16 bytes
```

Approximate memory:

```
~24 bytes per element
```

So it can use **~6× more memory**.

This also hurts **CPU cache performance**.

---

# 3️⃣ Cache Locality (Very Important)

With arrays:

```
[1][2][3][4][5]
```

All values are **contiguous in memory**.

With `List<Integer>`:

```
ArrayList → references
          ↓
      Integer objects scattered in heap
```

Memory layout:

```
ArrayList → [ref1][ref2][ref3]

ref1 → Integer(1)
ref2 → Integer(2)
ref3 → Integer(3)
```

CPU must **jump around memory**, causing **cache misses**.

---

# 4️⃣ Object Allocation Cost

When you do:

```java
list.add(i);
```

Java creates an **Integer object**.

In heavy loops like:

```
10^6 operations
```

This means **10⁶ object allocations**, increasing **GC pressure**.

---

# 5️⃣ Real Example

### Fast (primitive array)

```java
int[] arr = new int[n];
for(int i=0;i<n;i++){
    arr[i] = i;
}
```

### Slower (List)

```java
List<Integer> list = new ArrayList<>();
for(int i=0;i<n;i++){
    list.add(i);
}
```

Reasons:

* object creation
* boxing
* worse cache locality

---

# 🚀 Rule Used in Competitive Programming

Use:

```
int[]
long[]
char[]
```

instead of

```
List<Integer>
List<Long>
```

unless dynamic resizing is required.

---

# ⚡ When `List<Integer>` IS Better

Use it when you need:

* Dynamic resizing
* Frequent insert/delete in middle
* Collections API features

---

✅ **Interview takeaway sentence**

> Primitive arrays are faster than `List<Integer>` because they avoid autoboxing, reduce memory usage, and improve CPU cache locality.
